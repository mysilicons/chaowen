## 1. 需求确认

本次目标是在现有“朝闻”阅读器中增加联合早报文章阅读功能，流程为：

```text
读取中国频道页面
    → 提取当前主列表中的文章标题与链接
    → 在阅读器内展示文章列表
    → 用户选择文章
    → 读取对应文章详情页并提取正文
    → 使用阅读器自己的文字排版呈现
```

**交付核心是应用内文章列表与独立正文阅读。** 官网跳转只作为查看原文、受限内容或解析失败的辅助操作，不能代替正文阅读完成验收。

“只爬取这个网页”的范围定义为：该地址是唯一的文章发现入口；为取得完整文章，允许访问从其主列表直接提取出的文章详情页，以及阅读所需的图片。频道页通常提供列表而非所有文章全文，因此不能承诺只发出一次频道页请求就得到全部正文。

抓取深度固定为“入口列表 → 文章详情”，不递归跟进详情页的相关阅读、上一篇、下一篇、标签、作者、其他频道或全站搜索。首次读取频道页面，滚动接近列表底部时通过官网同一中国频道分页来源加载更早的文章；仅追加当前频道，不做全站历史回溯。选择文章时按需获取正文，不在刷新列表时批量下载全部文章。

## 2. 当前项目理解

### 2.1 架构与已有实现

当前项目是 Windows 桌面阅读器，采用 Flutter + Riverpod 界面和 Python 3.12 本地引擎，通过 stdin/stdout 上的 UTF-8 NDJSON 通信。Python 负责 HTTP、解析、SQLite、文件缓存和 PDF 合并；引擎随安装包分发，用户不需要另装 Python。

| `app/lib/state/providers.dart` | 按日期取报纸，阅读目标为 `{date,no}` | 新增独立文章列表和阅读目标状态 |

人民日报的数据组织为“日期 → 版面 → 文章／PDF”，早报本次的数据组织为“固定频道列表 → 单篇文章”。不将早报条目转换成假版面，也不提供早报 PDF 模式或整期合并。

### 2.2 实施时需要注意的现状

- 现有正文缓存和 PDF 归档不等同于通用文章收藏、导出、全文搜索或跨重启滚动位置恢复；这些不作为已有能力引用。
- SQLite 当前主要执行初始化 DDL，没有完整逐版本迁移框架，需要补充事务迁移，不能只递增版本常量。
- `Engine.handlers` 实际提供 `issue.page`、`storage.reveal`；现有 `docs/ipc.md` 中部分规划接口与代码不完全一致。新增协议以实际代码为基线，同步 Schema。
- `app/pubspec.yaml` 的版本与发布文档存在差异；发布时核对，本次不改版本。

## 3. 站点观察与技术验证边界

用户已确认：本机请求 `https://www.zaobao.com/news/china` 不会跳转到 `.com.sg`。应用由本机 Python 引擎直接访问 `.com`，列表及详情解析以该域名在本机返回的内容为准，不主动切换到 `.com.sg`。

2026-10-30 的网页工具曾呈现 `.com.sg` 频道及两篇详情页，其中可见标题、时间、作者、图片、正文及订户预览等元素。这些只能作为结构参考，不能作为本机重定向行为或 `.com` 页面结构的证据。[频道](https://www.zaobao.com/news/china)、[工具取得的公开文章样本](https://www.zaobao.com.sg/news/china/story20261028-9907100)、[工具取得的订户文章样本](https://www.zaobao.com.sg/news/china/story20261028-9905108)。

实施阶段已追加本机 httpx 实测：`.com` 频道 HTTP 200、无跳转；主列表选择器为 `main [data-testid="article-list"] article`，正文为 `article#article-body[data-testid="article-body"]`。本机烟测获得 27 篇、选中文章 7 段正文及 1 张已缓存图片。下表为后续模板变化时仍需复核的项目，不使用 `.com.sg` 样本替代这些实测。

| 核查项 | 需要得到的结论 |
| --- | --- |
| 频道原始响应 | 静态 HTML 是否包含目标主列表、链接和标题；是否需要额外动态加载 |
| 详情原始响应 | 正文容器、图片懒加载方式、元数据位置、订户／登录／验证页面特征 |
| 地址与身份 | 本机 `.com` 页面的实际详情链接、canonical、story ID 提取和去重规则；不默认将 canonical 或其他域名作为抓取目标 |
| 时间 | 字段是否带时区，发布时间与更新时间能否区分 |
| 主列表范围 | 排除导航、热门推荐、广告和跨频道入口；同篇文章多次出现只留一条 |
| 图片 | 实际媒体域名、内容类型、尺寸和许可范围；样本包含官方 CDN 地址 |

抓取只读取正常访问可取得的内容，不绕过登录、订阅或验证码。遇到预览应明确标注，不能将非空段落当作全文。站点使用条款与访问规则作为接入约束记录，不另设官网入口版或手工书签版替代本次需求；条款和 robots.txt 不能互相替代，参考资料见第 12 节。

| FR-02 | P0 | 获取固定入口的主列表 | 提取标题、详情 URL 和可取得元数据，去重并保留页面顺序 |

| FR-04 | P0 | 复用阅读体验 | 思源宋体、字号调节、深浅主题、文字选择复制可用；早报无 PDF 开关 |

P0 是本次核心交付，必须完成“频道列表 → 文章提取 → 阅读器呈现”全链路。P1 可在核心完成后补充，不改变抓取范围。

本次不做：其他频道、全站爬虫、全站历史回溯、递归推荐抓取、早报电子报 PDF、整期下载、手工链接导入、收藏系统、账户登录、云同步、推送、AI 摘要、导出或分享、视频／播客播放。正文中的视频或交互内容提供原文查看提示。

非功能要求：本地运行；缓存失败不破坏旧内容；正文与图片分别单通道串行；无后台定时刷新；单条 IPC 不超过 1 MiB；缓存命中列表目标 500ms 内展示，任务接收目标 300ms 内返回，实际需在约定测试机测量，网络完成时间不作固定承诺。

## 5. 界面设计

```text
朝闻侧栏
├─ 人民日报 → 现有书架与版面阅读
├─ 联合早报 → 中国频道列表 → 单篇文章阅读
├─ 下载中心 → 现有人民日报下载任务
└─ 设置
```

列表页顶部显示“中国频道”、手动刷新及最近成功刷新时间。每条至少显示标题，可选时间、作者、摘要和缩略图；字段缺失不阻止条目展示，不能用 URL 日期冒充精确发布时间。列表保留来源顺序，头条区最多展示前三篇的缩略图；不批量预取正文，目录按可视范围构建。

首次进入优先读缓存；没有缓存时触发一次当前频道获取。已有缓存则立即展示，由用户手动刷新。刷新失败保留旧列表并显示失败提示。初次加载、有效空列表、无法访问及结构解析失败采用不同状态。

阅读页提供返回、标题、作者、时间、字号和原文入口，正文采用阅读器自己的排版。返回恢复列表位置；文章切换时以文章 ID 绑定状态，避免慢请求覆盖后来选择的文章。

预览显示“当前为可访问的预览”；无法确认完整性时显示“无法确认内容是否完整”。这两种状态都不能标成“全文已缓存”。图片失败使用占位，不阻止文字阅读。原文按钮仅辅助查看官网，不是正常阅读的主路径。

## 7. 抓取与解析设计

### 7.1 链接发现边界

1. 本机引擎固定请求 `https://www.zaobao.com/news/china`；按照用户确认的访问行为直接使用 `.com`，不主动改写为 `.com.sg`。
2. 只在已验证的主新闻列表容器提取文章链接，不扫描全站导航的所有 `<a>`。
3. 仅接受经过验证的官方 HTTPS 域名及文章路径，移除已知追踪参数，规范化并去重。
4. 已进入当前快照或此前快照的文章可按篇读取；前端只传已登记 articleId，不接受任意抓取 URL。
5. 详情解析不产生新的抓取目标。即使详情中的相关阅读也属于中国频道，仍不继续跟进。
6. 默认文章请求范围为 `www.zaobao.com` 下的已验证详情路径；相对链接以本机实际响应 URL 解析。若遇到跨域文章链接、canonical 或重定向，先记录并验证，不自动切到 `.com.sg`，也不自动合并两个域名的内容。图片 CDN 单独按实际响应核查。

### 7.2 列表解析

在确认的主列表容器中提取标题、链接及可选的时间、作者、摘要、封面。使用稳定 story ID 或规范 URL 哈希去重，保留首次出现顺序。

选择器未命中时返回 `PARSE_ERROR`；只有识别出有效空列表模板时才返回空数组。刷新成功后事务替换当前快照；历史文章缓存可保留，但不能混入“当前页面列表”冒充刚抓到的条目。

### 7.3 正文解析

先校验 HTTP 状态、最终 URL、内容类型与页面模板，再提取标题、时间、作者和正文容器。按 DOM 顺序生成段落／图片块，排除广告、导航和推荐区域，同时保留推荐模块之后仍属于正文的段落。

不对全页所有 `<p>` 直接取文本；不执行页面脚本；不利用其他隐藏数据绕过当前访问状态。JSON-LD 等结构化数据只有在实际存在且含义经验证后才用于元数据补充，不能据此自动判定全文。

访问状态与内容完整性分别表达：`access=public|subscriber|login_required|blocked|unknown`，`contentState=full|preview|unknown|unsupported`。只有经验证的模板／数据证据才能判 full，文字长度和段落数量都不能单独作为证据。

### 7.4 HTTP 与媒体策略

早报单独客户端、单 worker 和调度锁，避免人民日报的重试、下载队列及熔断状态互相影响。正文／列表与图片各用独立的单 worker 和客户端，默认请求间隔 0.5 秒；已核查 `.com` 的 robots 允许访问。移除旧版固定 10 秒等待，仍遵守 429 等服务端限制。图片不占用正文任务队列。

单次连接约 10 秒、请求约 20 秒；暂时性网络错误／5xx 最多额外重试 2 次；401/403/404 不沿用人民日报的偶发重试策略；429 遵守秒数或 HTTP-date 的 Retry-After，不能因为现有客户端的等待上限而提前重试。

现有公开 HTTP 方法只返回 text／bytes，需要新增取得状态、最终 URL、ETag 和内容类型的接口。支持时使用条件请求；304 读取原缓存。每跳重定向均需校验，不在发出请求后才检查域名。拒绝局域网地址、非 HTTPS 和非白名单目标。

正文 HTML 建议限制为解压后 5 MiB、单图 10 MiB，并限制像素尺寸与图片数量；具体上限以样本验证调整。图片校验内容类型与签名，通过引擎按需下载；阅读页图片由引擎缓存并推送更新事件。首页仅前三篇头条直接加载 CDN 缩略图，限制解码宽度并使用 Flutter 图片缓存；滚动目录不为全部条目批量下载图片。

## 8. 数据与缓存

### 8.1 模型

`ZaobaoSummary` 包含 `articleId,url,title,author?,publishedAt?,updatedAt?,timeLabel?,thumbnail?`。时间采用详情页 JSON-LD 中带时区的字段；列表只有相对时间时保留 timeLabel，不把获取时间当发布时间，不跟进跨域 canonical。

`ZaobaoArticle` 增加 `blocks,access,contentState,fetchedAt,parserVersion,warnings`。Block 沿用现有 `p`／`img` 形态，图片保留 `src,local,caption`。未解析正文前 `contentState` 可为 `not_fetched`。

已验证 story 格式时提取稳定 ID；其他合法文章链接使用规范 URL 的 SHA-256。ID 不使用日期加列表序号，以免刷新排序导致错篇。同一 `.com` 文章的 URL 变体应去重，不预设与 `.com.sg` 地址等价，也不为取得规范 URL 另行访问该域名。

### 8.2 存储

沿用现有 `state.db`，新增：

| 表 | 关键内容 |
| --- | --- |
| `zaobao_articles` | articleId 主键、summary JSON、body JSON、read_at、accessed_at；正文中含访问／完整性及解析版本 |
| `zaobao_feed_items` | 当前快照版本、articleId、列表序号，固定为中国频道 |
| `zaobao_feed_state` | 最近成功刷新时间、next_page 和 has_more；支持官网分页，不实现条件请求 |

不增加来源注册表、频道配置表或收藏表。v3 迁移增量增加分页状态列，已有 v1/v2 库升级前分别备份；首次接入时新增早报表／索引，保留 issues、pages、旧缓存及下载路径。迁移前使用 SQLite backup API 备份，事务内建表并更新版本；失败回滚，不能在 WAL 活跃时只复制数据库主文件。

```text
现有缓存根目录/
  state.db
  text/、img/                         # 现有人民日报缓存
  # 早报正文存放 state.db 的 zaobao_articles.body
  zaobao/media/{urlHash}.{ext}
```

正文直接作为 JSON 存入 SQLite，在单次事务中更新，失败保留原内容；无需正文文件与数据库指针的两阶段同步。文字先提交，再逐步补齐图片，因此图片任务取消不丢失正文。图片使用受控 URL 哈希路径、临时文件与原子替换。

缓存命中先显示内容，不自动联网重抓；手动更新文章时重新判断权限和完整性。刷新失败不覆盖旧快照／正文。断网可读实际已缓存内容；缺图占位，无正文缓存时明确说明。

缓存预算为 300 MiB：先清理较旧图片，再按访问时间保留较近正文，已读元数据保留。SQLite 清理释放逻辑内容空间供后续复用，不保证数据库文件立即缩小。列表刷新不等于文章全部离线可用，预览缓存不等于全文缓存。

## 9. IPC 与异步任务

保持协议 v1 信封，`hello` 新增可选能力字段 `zaobaoReaderV1`；旧引擎缺少能力时提示需要匹配版本，不盲调新方法。新增错误码同步扩展现有 Schema 枚举。

| 方法 | 参数 | 返回／行为 |
| --- | --- | --- |
| `zaobao.feed.get` | `{}` | 本地快照、items、fetchedAt、stale；不联网 |
| `zaobao.feed.refresh` | `{}` | 从固定入口刷新，立即返回 jobId |
| `zaobao.article.get` | `{articleId}` | 本地正文及 cached 状态；不联网 |
| `zaobao.article.fetch` | `{articleId,refresh:false}` | 按篇后台获取，立即返回 jobId |
| `zaobao.task.get` | `{jobId}` | 查询 queued/running/succeeded/failed/cancelled 及错误／结果引用 |
| `zaobao.task.cancel` | `{jobId}` | 取消等待或后续请求，保留已有缓存 |
| `zaobao.cache.clear` | `{}` | 清理早报缓存，返回移除的逻辑内容与图片字节 |
| `zaobao.read.set` | `{articleId,read:true}` | 幂等写入已读状态 |
| `zaobao.original.open` | `{articleId}` | 用户点击时打开已登记的官网原文，返回 `{ok:boolean}` |

列表支持官网连续分页；远端页码由引擎保存，不接受前端任意 URL。本地通过 offset/limit 分页读取（默认 60、最多 100），避免持续滚动后单条消息超限。失败保留当前列表和游标，可重试。

事件 `zaobao.task.changed` 包含 `jobId,kind,articleId,state,error`，只传状态和结果引用。任务成功后前端重新调用 get 读取本地数据；事件丢失可查询任务。图片补齐通过 `zaobao.article.updated` 通知，只重读当前文章。进程内终态保留约 10 分钟，进程重启不自动续抓。

主线程先响应 jobId，再提交给独立早报线程池。现有 RPC 的 `_responded` 为共享状态，后台不能调用 `ctx.respond`／`write_ok`，只经写锁发送事件，避免破坏后续请求应答。相同文章并发点击合并任务，正文请求优先于尚未开始的可选图片请求。

正文建议预算 700 KiB，完整 NDJSON 信封严格低于 1 MiB；超限返回 `CONTENT_TOO_LARGE` 及辅助原文入口，不截断后标 full。二进制不进入协议，图片只传本地路径和源地址。

## 10. 错误与降级

| 状况 | 行为 |
| --- | --- |
| 网络超时／服务端错误 | 可手动重试，有缓存则保留并提示 |
| 429 | 显示可重试时间，调度器延迟请求 |
| 登录／订户预览 | 显示实际可用内容与状态，原文入口辅助；不尝试绕过 |
| 验证页／403 | 显示访问受限，不自动换身份或重复探测 |
| 404 | 原文不可用；可显示已有缓存并注明缓存时间 |
| 结构变化 | PARSE_ERROR，保留旧数据，记录解析版本 |
| 缺图 | 图像占位，正文继续可读 |
| 磁盘失败 | 不伪报缓存成功，保持已有缓存指针 |
| 完整性未知 | 明确标 unknown，不能当成功全文验收 |

这些是异常降级路径。正常公共文章必须能够在阅读器内呈现正文，不能将全部条目转为浏览器链接后声称功能完成。

## 11. 开发阶段与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| G0 页面实测 | 核查固定入口和代表性详情原始响应，形成真实选择器和测试样本 | 抓取深度、正文可得性、模板与受限状态可辨识 |
| G1 后端贯通 | 专用解析器、模型、HTTP 策略、缓存、迁移及 IPC | 固定入口列表 → 单篇正文 DTO 可端到端运行 |
| G2 界面呈现 | 入口、列表、正文、阅读设置、刷新与返回 | 应用内阅读完整闭环；不影响人民日报 |
| G3 打磨发布 | 错误态、图片、缓存管理、已读、打包与回归 | 安装包、旧库升级、离线与限速验证 |

粗估约 5–9 人日工程工作：G0 1–2、G1 2–3、G2 1–2、G3 1–2。以静态响应可读取所需内容为假设，不含复杂动态页面或外部接入等待；G0 后重新估算。

自动化测试沿用 pytest + respx、Flutter test，默认离线：

- 频道：主列表提取、顺序去重、导航／推荐排除、结构失效与真实空列表。
- 正文：段图顺序、图注、插入推荐后仍有正文、缺字段、预览及验证页识别。
- 范围：只请求固定入口及其直接登记文章；详情中的推荐、前后篇、标签绝不入抓取队列。
- 网络：并发 1、节流、429、403 不重试、逐跳重定向检查、体积限制与图片类型校验。
- 缓存与迁移：刷新失败保旧、损坏缓存、断网、原子写入失败、v1 升级及旧数据保留。
- IPC：jobId 先于事件、可查询终态、后台不干扰应答、大小限制、新错误码契约。
- 界面：正常文章在应用内可读、预览明确、字号／主题、快速切篇不串内容、返回恢复列表。

人工验收必须覆盖：从指定频道取列表；点击公共文章与原文比对标题和段图顺序；订户预览不标全文；刷新不批量获取所有正文；断网可读缓存；人民日报下载同时进行时仍可操作；在打包后的 Windows 应用中验证旧库升级、规则文件及图片缓存。

```powershell
# engine 目录
uv run pytest -q --basetemp=.pytest-tmp

# app 目录
flutter analyze
flutter test
```

实施阶段已执行解析、服务、迁移、网络、任务协议与 Flutter 阅读流程测试，并进行 `.com` 真实文章烟测。最终完整测试、构建与提交结果以实施日志为准。
