# 联合早报：无持久化与诊断日志

更新日期：2026-10-30。本文覆盖此前设计中的早报摘要、离线缓存和已读持久化方案。

## 用户可见行为

1. 首页、后续分页和头条均不显示标题下的摘要，后端也不再提取分页摘要字段。
2. 每次从侧栏进入联合早报，清空上次会话并重新请求固定中国频道入口。离开来源即释放早报数据；刷新失败显示错误，不恢复旧列表。
3. 同一会话内保留已获取的列表、正文、分页游标与已读标记，以支持返回目录和继续下滑；这些数据不写文件或数据库，进程重启后为空。
4. 正文图片通过网络按需展示，仅使用 Flutter 的内存图片缓存。没有早报图片落盘和后台图片下载队列。
5. 人民日报的下载、存档和设置继续使用原有机制。诊断日志是用户明确要求保留的运行数据。

## 会话与旧版数据

- `ZaobaoRepo` 是每个引擎实例独立的内存仓库，不依赖 SQLite 或文件目录。
- `zaobao.session.reset` 取消旧任务、清空仓库并递增会话代次。网络请求提交结果前检查取消状态与代次，防止已离开页面的旧请求污染新会话。
- 前端以自己的代次检查过滤晚响应，进入和离开来源时均重置；手动刷新同样清空后重新获取。
- 协议中的 `cached` 仅表示本会话内已有正文，保留字段名以减少接口变动，不代表持久化缓存。
- 数据库升级到 v4，删除 `zaobao_feed_items`、`zaobao_feed_state`、`zaobao_articles`，保留人民日报表。
- 启动时清除当前缓存目录内的旧 `zaobao/` 子目录。删除前检查真实路径，拒绝该目录为符号链接或 junction；失败会写警告日志。
- 历史版本创建的 `state.db.*.bak` 不自动删除。删除旧表属于逻辑清理，不承诺对历史备份或数据库空闲页做安全擦除。新版不会再向数据库写入早报内容。

## 日志设计

默认目录：`%LOCALAPPDATA%\rmrb-reader\logs`。开发和故障复现时可用 `CHAOWEN_LOG_DIR` 指定其他目录。通过早报页「日志」或「设置 → 诊断日志」打开。

| 文件组 | 单文件上限 | 份数（含当前） | 总预算 |
| --- | --- | --- | --- |
| `app.log`、`.1`、`.2` | 1 MiB | 3 | 3 MiB |
| `engine.log`、`.1`、`.2` | 1 MiB | 3 | 3 MiB |
| `native.log`、`.1` | 256 KiB | 2 | 512 KiB |

日志总预算约 **6.5 MiB**，另有极小的锁文件。达到上限即轮转覆盖最旧文件，单条 Dart/Python 日志限制为约 8 KiB。UTF-8 按字节计算，Python 禁用 Windows 换行转换，避免字符计数与实际大小不一致。多进程通过各自的锁文件协调轮转；文件不可写或锁竞争时允许丢弃诊断记录，不阻塞阅读或触发新的崩溃。

- 前端：启动、引擎生命周期、请求方法与编号、超时、异常类型和堆栈；接管 Flutter 错误、未捕获异步错误与平台错误。
- 引擎：启动退出、RPC 耗时、HTTP 请求耗时与字节数、失败代码、分页及文章任务状态、安全异常堆栈；stdout 保持纯 NDJSON。
- Windows 原生层：未处理 SEH 的异常代码、地址、线程和关键寄存器，以及未处理 C++ 异常标记。其记录是轻量故障信息，不生成完整内存转储。
- 不记录文章标题、摘要、正文、请求参数、响应内容、Cookie 或鉴权值。异常记录使用类型和代码位置，避免异常消息携带文章内容。路径和文章 ID 可能出现在日志中。
- 系统强制终止、断电及日志目录不可写等情形无法保证最后一条崩溃信息落盘。
