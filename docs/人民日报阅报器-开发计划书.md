### E-04 HTTP 客户端（限速是第一约束）

**技术步骤**
1. `net/limiter.py`：令牌桶，参数 `rate=1/s`，`burst=1`；
2. `net/client.py`：`HttpClient.get_text()` / `stream_to_file()`；
3. 超时：connect 10 s / read 20 s / write 20 s；
4. 重试：连接错误、超时、5xx → 3 次，退避 2/4/8 s + ±20% 抖动；429 读 `Retry-After`；**403/404 重试 1 次**；
5. 熔断：连续 8 次失败 → 抛 `CIRCUIT_OPEN`；
6. `User-Agent: RMReader/0.3 (personal reading; low-rate)`。

**产出**：`net/client.py`、`net/limiter.py`、`tests/test_client.py`（respx）

**验收**

| 检查 | 方法 | 通过标准 |
| --- | --- | --- |
| 限速生效 | 连续 5 次请求，记录时间戳 | 相邻间隔 ≥ 0.9 s |
| 5xx 重试 | respx 前 2 次 503、第 3 次 200 | 最终成功，请求计数 == 3 |
| 404 只重试一次 | respx 恒 404 | 请求计数 ≤ 2，抛 `HTTP_ERROR` |
| 429 遵守 Retry-After | respx 返回 `Retry-After: 2` | 间隔 ≥ 2 s |

### E-05 下载器（续传 + 原子写）

**技术步骤**
1. `net/downloader.py`：`download(url, dest: Path)`
2. 先写 `dest.with_suffix(".part")`；
3. `.part` 存在且 `size > 0` → 发 `Range: bytes={size}-`；返回 206 追加；返回 200 则清空重下；
4. 完成后 `flush + os.fsync` → `os.replace()` 原子改名；
5. 校验：魔数 `%PDF-`、体积 ≥ 50 KB。

**产出**：`downloader.py`、`tests/test_downloader.py`

**验收**

| 检查 | 方法 | 通过标准 |
| --- | --- | --- |
| 正常下载 | mock 返回 1 MB 数据 | 文件存在、体积一致、无 `.part` 残留 |
| 断点续传 | 预置 500 KB `.part`，mock 返回 206 | 最终体积 == 完整长度，`Range` 头以 `bytes=512000-` 开头 |

| 超大 PDF（假 50 MB） | 不 OOM，进度可见 |

## 10. 风险与变更控制

### 10.1 已知风险

| 风险 | 触发信号 | 预案 |
| --- | --- | --- |
| 站点改版 | 解析命中 0 | 改 `rules/v2.yml`；失败样本入库做回归 |
| pdfrx API 变动 | 编译报错 | 锁死 `pdfrx: ^2.10.1`，升级单独排期 |
| 协议被日志污染 | 界面随机 `FormatException` | 断言 stdout 纯净的测试常驻 |
| 双进程打包失败 | 打包后引擎找不到 | 引擎路径解析加日志；dev/release 两套路径都要测 |
| 字体缺字 | 出现豆腐块 | `fontFamilyFallback` 兜底；收集缺失字补充子集 |
| Windows 开发者模式被关 | 构建即失败 | 见设计文档 §4.2；写进 README 排错 |

### 10.2 时间风险

- 任一任务超预估 **50%**：立刻停下来记录原因，评估是否拆分；
- 连续两个任务超预估：重估阶段工期，调整后续顺序（优先保 Gate 可演示）。

### 10.3 变更流程

1. 提出变更（改需求/改技术）→ 写清影响面（任务、工期、Gate）；
2. 更新设计文档 + 本计划书（版本号 +1，变更记录追加）；
3. 只有更新后计划书里出现的任务才允许开发。
