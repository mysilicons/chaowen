## 0. 结论先行

1. **产品定位不变**：一个能"翻、看、存"的桌面阅报器。
2. **架构变成两段**：Flutter（界面 + PDF 渲染 + 文字排版）↔ Python 引擎（抓取 + 解析 + 合并 + 状态）。
3. **Flutter 的收益**：像素级一致的自绘 UI、热重载带来的迭代速度、`pdfrx` 直接把 PDFium 做成 GPU 渲染的滚动视图，比自研 PDF 控件省 3–4 天。
4. **Flutter 的代价**：多一个运行时（Dart + Python sidecar），打包链路从 1 条变 2 条，安装包约 80–100 MB。**本机尚未安装 Flutter SDK**（实测 `flutter not found`），需先装工具链。
5. **双模式可以同时交付**：两条阅读路径共用同一份"版面页解析"结果，PDF 模式依赖 `merged.pdf`，文字模式依赖 `text/*.json`，并行开发的实际增量只有文字排版，**不是两倍工作量**。
6. **单版删除的前提**：合并文件必须通过"页数 == 版数 + 可打开"校验后才删除单版；合并失败则保留单版。删除不可撤销（可重新下载）。

## 1. 产品定位

### 1.1 一句话

> 一个能"翻、看、存"的《人民日报》桌面阅报器 —— 像翻报纸一样浏览当天版面，像读网页一样读正文，需要留档时一键下载并合成整期 PDF。

### 1.2 用户与场景

| 场景 | 用户动作 | 产品响应 |
| --- | --- | --- |
| 每天早上的例行阅读 | 打开应用 | 书架直接定位今天，展示 20 个版面缩略图 |
| 只想看某版头条 | 点版面 → 文字模式 | 抓 1 页 HTML（<100 KB），秒开，可复制 |
| 想收藏这一期 | 点"下载本期" | 逐版低速下载 → 合并 → 删除单版 → 只留一本 |
| 补一个月的存档 | 下载中心 → 批量 | 区间 + 预估耗时/体积 + 后台排队 |
| 翻旧报纸 | 书架月历 → 点日期 | 已下载直接读；未下载先出缩略图预览 |

### 1.3 范围边界

**做**：新版站点（2024-12-01 起）的版面浏览、文字阅读、PDF 下载与合并、本地书库管理。

**不做**：
- ❌ 旧版站点（`/rmrb/html/`、`/rmrb/images/`）；
- ❌ 1946–2020 图文数据库（需授权）；
- ❌ 账号、云同步、分享导出、多报纸；
- ❌ 任何绕过限制、代理池、指纹伪装。

## 2. 站点实测分析（只保留新版）

### 2.1 URL 体系

| 资源 | 规则 | 可构造性 |
| --- | --- | --- |
| 版面页 | `/rmrb/pc/layout/{YYYYMM}/{DD}/node_{NN}.html` | ✅ 可构造 |
| PDF | `/rmrb/pc/attachement/{YYYYMM}/{DD}/{uuid}.pdf` | ❌ **UUID，必须解析** |
| 版面缩略图 | `/rmrb/pc/pic/{YYYYMM}/{DD}/{uuid}.jpg.2` | ❌ 必须解析 |
| 正文页 | `/rmrb/pc/content/{YYYYMM}/{DD}/content_{id}.html` | ❌ 必须解析 |
| 正文配图 | `/rmrb/pc/pic/{YYYYMM}/{DD}/{uuid}.jpg` | ❌ 必须解析 |

> `attachement` 是站点自身的拼写错误，必须原样使用。

**新版起点 2024-12-01**（实测 `202412/01` 返回 200，`202411/30` 返回 404）—— 这是回溯下限。

### 2.3 正文页结构

```html
<div class="article">
  <h1><p> “更加清醒坚定地推进反腐败斗争”（总书记的人民情怀） </p></h1>
  <p class="sec">…副标题…</p>
  <!--enpcontent-->
    <p>　　第一段正文…</p>
    <p class="not-indent patt"><img src="../../../pic/202610/29/{uuid}.jpg"></p>
  <!--/enpcontent-->
</div>
```

**元数据藏在 HTML 注释里**，是结构化的：

```html
<!--enpproperty
  <date>2026-10-29 00:00:00:0</date>
  <author>本报记者  张  洋</author>
  <subtitle></subtitle>
  <paperarticleid>30188305</paperarticleid>
  <title><p> … </p></title>
/enpproperty-->
```

→ 一条正则取 `author` / `subtitle` / `paperarticleid`，比解析 DOM 稳。

### 2.4 资源特征

| 项 | 实测值 | 用途 |
| --- | --- | --- |
| 单版 PDF | 1 页、1016.99×1452.60 pt；**实测 0.64–14.13 MB，均值约 3.1 MB** | 合并、容量预估 |
| 整期体积 | **62.7 MB**（20 版；其中 3 个广告版合计 32.1 MB，占 51%） | 存储与耗时预估 |
| PDF 结构 | `%PDF-1.4`，99 处 `/Font` | **有文字层，无需 OCR** |
| 传输 | `Accept-Ranges: bytes`、`206`、`ETag` | 断点续传、幂等 |
| 防盗链 | 无 | 无需伪造 Referer |
| 发布时刻 | 约北京 05:58 | 每日 07:00 后内容稳定 |
| 版面缩略图 | 400×575 JPEG | 书架/预览网格 |
| 版数 | 工作日 **20**；周六日 **8**；国庆 **8** | **不可硬编码** |
| 稳定性 | 有效 URL 偶发 404/403 | 重试策略必需 |

### 2.5 版型分布（决定文字模式的表现）

以 2026-10-29 为例：

| 版号 | 版名 | 文章数 | 文字模式表现 |
| --- | --- | --- | --- |
| 01–07 | 要闻 | 6–8 篇 | 目录 + 全文 |
| 08 | 广告 | **1 篇** | 单篇渲染 |
| 09–15 | 理论 / 各地传真 / 政治 / 文化 / 社会 / 体育 | 5–8 篇 | 正常 |
| 16 | 广告 | 1 篇 | 单篇渲染 |
| 17–20 | 国际 / 民主政治 / 法治 / 副刊 | 5–8 篇 | 正常 |

> 存在"整版只有 1 篇文章 + 1 张图"的版面，也存在"图片报道"（正文 1 图 + 3 行图说）。**文字模式必须能优雅处理 0/1/N 篇**。

### 3.3 关键用户故事

**US-1｜晨读**
> 打开就能看见今天的 20 个版面，点第 3 版读文字，全程不下 PDF。

验收：启动 → 书架今日 → 点 03 版 → 3 s 内出内容（首次），之后 < 500 ms（缓存）。

**US-2｜留档**
> 点一下，剩下的交给它；慢没关系，别中断；最后只留一本。

验收：点"下载本期" → 队列 20 项 → 完成后合并 → **校验页数 == 20** → 删除 20 个单版 → 目录里只剩 `人民日报_2026-10-29.pdf` + `manifest.json` → 通知"已归档 62.7 MB"。

**US-3｜补档**
> 补上整个 10 月。

验收：批量 → 10-01～10-29 → 显示"29 天 · 约 480 版 · 约 540 MB · 预计 38 分钟" → 可暂停 → 关掉重开，已完成的天不重下。

## 4. 技术选型

### 4.1 整体形态：Flutter + Python 引擎

```
┌──────────────────────────────┐        ┌─────────────────────────────┐
│  Flutter 应用进程（Dart）      │  IPC   │  Python 引擎进程（uv 环境）   │
│  · 界面 / 主题 / 动效          │◀──────▶│  · HTTP 抓取（限速/续传）     │
│  · PDF 渲染（pdfrx/PDFium）    │ NDJSON │  · HTML 解析（selectolax）    │
│  · 文字排版（Flutter Widget）  │ stdio  │  · PDF 合并（pypdf）          │
│  · 状态管理（Riverpod）        │        │  · 状态库（SQLite）           │
└──────────────────────────────┘        └─────────────────────────────┘
```

为什么这样切分：

| 职责 | 放在哪 | 理由 |
| --- | --- | --- |
| 界面、动效、PDF 渲染、文字排版 | Flutter | 自绘引擎，三平台像素一致；pdfrx 现成 |
| 网络抓取、HTML 解析、PDF 合并、状态 | Python | 已有成熟库（httpx/selectolax/pypdf），且 uv 环境已就绪 |
| 任务编排 | 两侧各一半 | 引擎管执行与状态，Flutter 管展示与操作意图 |

**反方意见（记录下来）**：双进程有额外的打包与调试成本；若团队只有一个人且更在意"少一个运行时"，纯 Dart（§4.7）更省事。

### 4.2 Flutter 桌面可行性（**已在本机完成验证**）

| 项 | 实测 / 结论 |
| --- | --- |
| Flutter | ✅ **3.47.8 stable**（`D:\soft\flutter`），满足 `pdfrx` 的 ≥3.47.0 |
| Dart | ✅ **3.13.7**，满足 `sdk: ^3.13.0` |
| 编译工具链 | ✅ VS Community 2026 18.11 + Windows SDK 10.0.26100 |
| 无插件工程构建 | ✅ 通过（90 s） |
| **带插件工程构建** | ✅ 通过（84 s），`pdfrx` / `url_launcher` 原生插件正常 |
| **PDFium 运行时** | ✅ 实测打开真实版面 PDF：1 页、1016.99×1452.60 pt、提取文本 7170 字、渲染 900×1285 |

> **唯一的部署陷阱：Windows 开发者模式。**
> 关闭时任何含插件的 `flutter build windows` 都会直接失败：
> `Building with plugins requires symlink support. Please enable Developer Mode…`
> 本项目依赖 `pdfrx`、`window_manager`、`path_provider`、`shared_preferences` 四个插件，因此**必须先开启开发者模式**（设置 → 系统 → 开发者选项），或以管理员身份构建。构建参数里没有可绕过该限制的开关。

### 4.3 PDF 渲染：pdfrx

| 方案 | 评价 |
| --- | --- |
| **pdfrx 2.10.1** | ✅ 基于 PDFium，GPU 渲染连续滚动、内置缩略图与文本提取；Win/macOS/Linux 全支持 |
| pdfx | ⚠️ 同类，功能较少，维护活跃度低于 pdfrx |
| Flutter WebView + PDF.js | ❌ 桌面端 WebView 不一致，体积大 |
| 自绘（FFI 调 pdfium） | ❌ 重复造轮子，等于重写 pdfrx |

**决策：pdfrx。** 直接获得：连续滚动、缩放、单页渲染（做缩略图）、文本提取（做"复制本页"）。

### 4.4 前后端通信：NDJSON over stdio

| 方案 | 评价 |
| --- | --- |
| **stdio + NDJSON** | ✅ 无端口、无防火墙弹窗、生命周期与父进程绑定、天然隔离 |
| 本地 HTTP（127.0.0.1） | ⚠️ 需要端口分配、token 鉴权、防火墙例外 |
| gRPC / ZeroMQ | ❌ 依赖重，协议生成成本大于收益 |

**决策：NDJSON（每行一个 JSON）走 stdin/stdout，stderr 专用于日志。**

协议设计（详见 §7.2）：

```jsonc
// 请求（Flutter → 引擎）
{"id":1,"method":"issue.parse","params":{"date":"2026-10-29"}}

// 响应（引擎 → Flutter）
{"id":1,"ok":true,"result":{"date":"2026-10-29","pageCount":20,"pages":[…]}}

// 事件（引擎 → Flutter，单向推送，无 id）
{"event":"download.progress","data":{"date":"2026-10-29","pageNo":17,"done":16,"total":20}}
```

### 4.7 备选：纯 Dart 方案（如不需要 Python）

| 环节 | 纯 Dart 实现 | 风险 |
| --- | --- | --- |
| HTTP | `package:http` / `dio` | 低 |
| HTML 解析 | `package:html`（支持 `querySelector`） | 低，但容错不如 selectolax |
| PDF 合并 | `pdfrx` 的合并能力或 `syncfusion_flutter_pdf` | **中高**：20 文件合并的稳定性未验证 |
| 状态库 | SQLite via `drift` | 低 |
| 打包 | 单 Flutter 应用，无 sidecar | **最低**（约 45 MB） |

**判断**：纯 Dart 能把安装包从 ~90 MB 降到 ~45 MB，并消灭双进程；代价是**合并稳定性**与**解析健壮性**要重新验证。若你希望"只用一个运行时"，这是可行路线，但需要额外 2–3 人日做技术验证。

本方案（v0.3）选择 Flutter + Python：**先保证正确，再谈精简**。

## 5. 架构设计

### 5.1 分层

```
┌───────────────────────────────────────────────────────────────┐
│  Flutter 表现层                                                │
│  ├ views: Library / Reader / Downloads / Settings              │
│  ├ widgets: ThumbGrid / PageStrip / PdfPane / TextPane / Toast  │
│  └ theme: 设计令牌（颜色/字号/间距）+ 浅色/深色                   │
├───────────────────────────────────────────────────────────────┤
│  Flutter 状态层（Riverpod）                                     │
│  ├ issueProvider     当前日期的版面与状态                        │
│  ├ queueProvider     队列快照（由引擎事件驱动）                   │
│  ├ readerProvider    版号、模式、滚动位置                         │
│  └ libraryProvider   月历聚合、存储统计                          │
├───────────────────────────────────────────────────────────────┤
│  IPC 层（Dart）：EngineClient                                   │
│  · 进程生命周期、握手、请求 id 路由、事件流、超时、重连            │
└───────────────────────┬───────────────────────────────────────┘
                        │ NDJSON / stdio
┌───────────────────────▼───────────────────────────────────────┐
│  Python 引擎                                                    │
│  ├ api/        方法路由（issue.parse / download.start / …）      │
│  ├ services/   下载队列、书库、合并、正文抓取                     │
│  ├ site/       v2 解析（规则 YAML）                              │
│  ├ net/        限速、重试、续传                                   │
│  └ store/      SQLite（唯一写入方）                              │
└───────────────────────────────────────────────────────────────┘
```

**关键原则：SQLite 只由引擎写，Flutter 不碰数据库。**
Flutter 的一切状态都来自 IPC 返回值与事件推送 —— 避免两个进程抢同一份状态。

### 5.2 进程与线程模型

```
Flutter 主 Isolate ── UI 渲染、手势
   │
   ├─ EngineClient（异步，监听 stdout 行流）
   │
   └─ 轻量解析（仅本地 JSON → 模型），不阻塞帧

Python 引擎进程
   ├─ 主线程：读 stdin（逐行请求）→ 派发
   ├─ ThreadPoolExecutor(max_workers=2)：下载 / 抓取 / 合并
   └─ 事件写线程：向 stdout 输出 NDJSON（加锁，保证整行原子）
```

规则：
- **stdout 只能输出协议 JSON**，任何调试打印必须走 stderr（否则协议被污染 —— 这是双进程方案最常见的坑，测试里要专门断言）；
- 引擎单实例，Flutter 启动时拉起，退出时 `kill`；引擎异常退出 → Flutter 显示"引擎未响应"并提供重启；
- 合并等重任务在引擎线程池执行，Flutter 侧只显示进度。

**单版 PDF 的临时位置**：`{缓存目录}/tmp/{date}/{nn}.pdf`，合并成功后**直接删除**，从不进入下载目录 —— 这样"默认删除单版"在物理上就是自然结果，而不是"下载后再删"。

| 方案 | 说明 |
| --- | --- |
| **A. 单版下到 tmp，合并后删（推荐）** | 下载目录永远只有成品；中断时残留由启动清理 |
| B. 单版下到下载目录，合并后删 | 用户可能在中途看到一堆碎片文件，体验差 |

### 5.5 完整数据流

```
用户点"下载本期"
   → Flutter: EngineClient.call("download.start", {date, pages})
   → 引擎: 建任务 → 逐版 fetch PDF → 写 tmp/{nn}.pdf → 校验
        └─ 每完成一版: emit {"event":"download.progress", …}
   → Flutter: 收到事件 → 更新进度条
   → 全部完成: 引擎 pypdf 合并 → 校验页数 → 删除 tmp 单版 → 写 manifest
        └─ emit {"event":"issue.archived", …}
   → Flutter: 刷新书架 → 通知 → 可选跳转阅读
```

## 7. 详细设计

### 7.1 下载引擎（低速是硬约束）

| 层 | 参数 | 默认 | 硬上限 |
| --- | --- | --- | --- |
| 档位 | 并发 / 间隔 | 标准 = 1 / 1.0 s | — |
| 令牌桶 | 单域名 req/s | 1 | **2** |
| 代码常量 | `MAX_CONCURRENCY` | 2 | 不可配置突破 |

| 档位 | 并发 | 间隔 | 单期预估 |
| --- | --- | --- | --- |
| 省流 | 1 | 2.0 s | ≈ 2 min |
| **标准** | 1 | 1.0 s | ≈ 45 s |
| 较快 | 2 | 0.6 s | ≈ 55 s（需二次确认） |

- 请求间 ±20% 抖动；UA `RMReader/0.3 (personal reading; low-rate)`；
- 连续 8 次失败 → 熔断，暂停队列；
- 重试：连接/超时/5xx → 3 次退避（2/4/8 s）；429 读 `Retry-After`；**403/404 重试 1 次**（实测有效 URL 会抖动）。

### 7.2 IPC 协议

**握手**

```jsonc
→ {"id":0,"method":"hello","params":{"protocol":1,"client":"rmrb-reader/0.3"}}
← {"id":0,"ok":true,"result":{"protocol":1,"engine":"0.3.0","python":"3.12.14"}}
```

**方法表**

| method | 参数 | 返回 |
| --- | --- | --- |
| `issue.parse` | `{date}` | `{date, pageCount, pages:[{no,title,thumbUrl,pdfUrl,articles:[…]}]}` |
| `issue.status` | `{date}` | `{status, pageCount, mergedPath, bytes}` |
| `library.month` | `{year, month}` | `[{date, status, bytes}]` |
| `download.start` | `{date, pages?}` | `{jobId}` |
| `download.pause` / `resume` / `cancel` | `{jobId}` | `{ok}` |
| `batch.start` | `{from, to, skipExisting}` | `{jobId, days, estBytes, estSeconds}` |
| `article.page` | `{date, pageNo, refresh?}` | `{pageNo, title, articles:[{title,author,blocks:[…]}]}` |
| `merge.retry` | `{date}` | `{ok, path}` |
| `settings.get` / `settings.set` | `{}` / `{patch}` | 配置快照 |
| `storage.stats` | `{}` | `{bytes, byYear}` |
| `reveal` | `{path}` | `{ok}` |

**事件**

| event | 载荷 |
| --- | --- |
| `download.progress` | `{jobId, date, pageNo, done, total, bytesPerSec}` |
| `download.page` | `{jobId, date, pageNo, status}` |
| `issue.archived` | `{date, path, bytes, deletedSingles:true}` |
| `job.finished` | `{jobId, ok, error?}` |
| `engine.log` | `{level, message}`（低频摘要，详细日志仍走 stderr） |

**错误信封**

```jsonc
{"id":7,"ok":false,"error":{"code":"PARSE_ERROR","message":"版面页结构变化","detail":"selector div.news matched 0"}}
```

**硬性规则**：
- 一行一个 JSON，UTF-8，无 BOM，行内不允许真实换行；
- stdout 只允许协议消息；任何 `print()` 都是 bug，测试必须覆盖；
- 单条消息 > 1 MB 视为异常并丢弃（防内存爆）；
- 请求默认超时 30 s，下载类方法不设超时（用事件报进度）。

### 7.3 合并与"删除单版"

```
下载到 {cache}/tmp/{date}/{nn}.pdf
   ↓ 全部页 done
pypdf 合并 → {download}/{date}/人民日报_{date}.pdf
   ↓ 校验
① 文件可打开  ② 页数 == 版数  ③ 每页 MediaBox 合理
   ↓ 全部通过
删除 {cache}/tmp/{date}/ 整个目录
   ↓
写 manifest.json（记录 deletedSingles: true）
```

**安全条件（缺一不可）**：
1. 全部版 `done`（部分失败不进入合并）；
2. 合并文件页数严格等于版数；
3. 合并文件能被 pypdf 重新打开并读取首末页；
4. 删除操作是**删缓存目录**，不是删用户目录里的东西。

**失败路径**：
- 合并抛异常 → 保留单版，状态 `merge_failed`，UI 给「重试合并」；
- 校验不过 → 同上，且不覆盖已有合并文件（先写 `.tmp` 再原子改名）。

**不可逆提示**：删除后无法从本地恢复单版；重新下载需联网。UI 在首次开启"删除单版"时明确告知一次。

### 7.4 PDF 渲染（Flutter / pdfrx）

```dart
PdfViewer.file(
  mergedPath,
  initialPage: pageNo - 1,
  controller: controller,
  params: PdfViewerParams(
    maxScale: 3.0, minScale: 0.5,
    pageAnchor: PdfPageAnchor.top,
    onPageChanged: (page) => reader.setPage(page + 1),
  ),
)
```

- 合并 PDF 的页码 = 版号 − 1，翻版即 `controller.goToPage(pageNo - 1)`；
- 缩略图：`PdfDocument.openFile` → `page.render(width: 160)`，批量生成后缓存到 `thumbs/`，避免每次进书架都渲染；
- 文本复制：`PdfPage.loadText()` → 复制到剪贴板（P2）；
- 内存：pdfrx 内置页面缓存；20 页 × 1.17 MB 的整期文件对桌面端无压力。

### 7.5 文字模式：解析（Python）

```
node_NN.html
  ├─ p.left.ban            → 版号 / 版名
  ├─ div.news ul li a      → 本版文章列表（有序）
  └─ img[src$=".jpg.2"]    → 版面露图（纯图版兜底）

content_{id}.html
  ├─ div.article h1        → 标题
  ├─ p.sec                 → 副标题
  ├─ <!--enpproperty …-->  → author / subtitle / paperarticleid
  └─ <!--enpcontent-->…    → 有序块：p(段落) / p>img(图片)
```

`rules/v2.yml`：

```yaml
layout:
  page_label: "p.left.ban"
  abstracts: "div.news ul li a"
  thumb: "div.paper img[src$='.jpg.2']"
  pdf: "div.paper-bot a[href$='.pdf']"
article:
  title: "div.article h1"
  subtitle: "div.article p.sec"
  meta_comment: "<!--enpproperty([\\s\\S]*?)-->"
  body: "<!--enpcontent-->([\\s\\S]*?)<!--/enpcontent-->"
```

输出结构（IPC 直传，Flutter 直接渲染，不再解析 HTML）：

```json
{
  "pageNo": 1, "title": "要闻",
  "articles": [
    {
      "title": "…", "author": "本报记者 张 洋", "subtitle": null,
      "blocks": [
        {"type": "p", "text": "在纪念中国工农红军长征胜利90周年大会上…"},
        {"type": "img", "src": "https://…/pic/…jpg", "local": "/cache/img/ab12.jpg", "caption": "图为…"}
      ]
    }
  ]
}
```

**为什么要转成 blocks**：Flutter 端用 `Column` + `Text`/`Image` 渲染，**排版完全可控**（首行缩进、行高、图说样式），比把 HTML 塞进 WebView 或 flutter_html 更稳更快。

### 7.6 文字模式：渲染（Flutter）

- 每篇：`Text(title, style: titleStyle)` → 作者行 → `Wrap` 的 blocks；
- 段落：`Text(text, textIndent: 2 * fontSize, height: 1.9, textAlign: TextAlign.start)`；
- 图片：`Image.file(File(local), fit: BoxFit.fitWidth)`，点击 → `showDialog` 全屏；
- 图说：小一号、居中、灰色；
- 文章分隔：32 px `SizedBox` + `Divider` + 居中菱形；
- 目录抽屉：`Drawer` 或侧滑面板，`Scrollable.ensureVisible` 跳转；
- 选中复制：`SelectionArea` 包住整页（Flutter 3.3+ 原生支持，这也是选 Flutter 的一个小福利）。

### 7.7 文字模式的"每版情况"（重点）

| 版型 | 判定 | 渲染策略 |
| --- | --- | --- |
| **常规版** | 文章数 ≥ 2 | 目录 + 文章流，按 `div.news` 顺序 |
| **单篇版** | 文章数 == 1 | 直接渲染，无目录 |
| **整版广告 / 纯图版** | 文章数 ≤ 1 且无文本段落 | 提示条「本版为图片版，建议切换 PDF」+ 展示版面图（已归档则用合并 PDF 第 N 页渲染 1200 px；未下载用 400×575 缩略图并标"低清预览"） |
| **图片报道** | 1 图 + 少量说明段 | 图置顶居中，说明在下 |
| **0 篇** | `div.news` 为空 | 空态 + [切换 PDF] [下载本版] |
| **解析失败** | 选择器全失败 | 错误态 + [重试] [切换 PDF] [查看诊断] |

配套：
- 版条上给纯图版加 `▣` 角标；
- 首次切到纯图版时 Toast 提示"已保持 PDF 模式"，记住选择不再打扰。

### 7.8 状态机

```
Issue: absent → downloading → partial → merging → archived
                        ↘ failed(可重试)
Page:  absent → queued → downloading → verifying → done
                                  ↘ failed / corrupt(可重试)
```

| 状态 | 书架 | 版条 | 主按钮 |
| --- | --- | --- | --- |
| absent | ○ | 虚线框 | 下载本期 |
| downloading | ◐ + 进度环 | 转圈 | 暂停 |
| partial | ◐ | 已完成实心 | 继续下载 |
| archived | ● | 实心 | 阅读 |
| failed | ○ + 红点 | 红点 | 重试 |

### 7.9 错误与降级

| 错误 | 文案 | 处理 |
| --- | --- | --- |
| 引擎启动失败 | "后台服务未启动，请重试" | 自动重启 1 次，仍失败给诊断入口 |
| 引擎崩溃 | "后台服务异常退出" | 重启 + 任务恢复（未完成任务标记失败） |
| 网络不可达 | "网络不可用，已切换到离线内容" | 顶部黄条 |
| 429/403 | "访问过于频繁，已暂停 60 秒" | 自动退避 |

| 磁盘满 | "磁盘空间不足，已暂停" | 暂停队列 |
| 合并失败 | "合并失败，单版已保留" | `merge_failed` + 重试 |
| 目录被移除 | "下载目录不可访问" | 打开设置 |

## 10. 里程碑（双模式同期交付）

| 阶段 | 交付 | 内容 | 估时 |
| --- | --- | --- | --- |
| **M1** | 引擎可跑 | uv 工程、限速客户端、v2 解析、单日下载到 tmp、SQLite | 2.5 人日 |
| **M2** | 打通链路 | IPC 协议 + `EngineClient`、Flutter 骨架、书架、缩略图、下载队列 | 2.5 人日 |
| **M3** | **双模式一步到位** | 合并 + 删除单版；PDF 阅读（pdfrx）；文字阅读（解析→blocks→排版）；模式切换 | 3.5 人日 |
| **M4** | 能交付 | 批量下载、设置/首启向导、主题、打包两条链路、测试 | 2 人日 |

合计 **约 10.5 人日**。

**为什么双模式能"一步到位"**：
- 两者共用同一份 `issue.parse` 结果（版号、标题、URL），**前置依赖只有一个**；
- PDF 模式只需"合并 + pdfrx"，文字模式只需"blocks + Column"，二者互不阻塞；
- 真正的增量是文字排版与版型兜底（约 1.5 人日），不是"再来一遍"。

> 前版把文字模式排到 M3 最后，是因为错误假设了"PDF 先稳定再谈文字"；实际上文字模式反而是**首次打开就能用**的轻量路径，应该与 PDF 同期。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **Flutter SDK 未安装** | 界面工作无法开始 | 先装 SDK + VS C++ 工具链；引擎可并行开发 |
| 双运行时打包 | 体积 80–100 MB、链路复杂 | 引擎用 PyInstaller onedir 内嵌；两条构建脚本固化到 `scripts/` |
| 协议被日志污染 | 界面随机报错 | stdout 只走协议；测试断言纯净性 |
| 引擎崩溃 | 界面全瘫 | 自动重启 + 状态恢复；关键状态落 SQLite |
| 站点改版 | 解析全废 | 规则 YAML + 分级降级 + 保存原始 HTML |
| UUID 不可构造 | 无法离线推算 | 必须解析；结果入库 |
| 限流/封禁 | 下载中断 | 1 并发 1 s；熔断；不提供"极速" |
| 删除单版后合并文件损坏 | **存档丢失** | 删除前四重校验；先写临时文件再原子改名；保留 manifest 以便重下 |
| 字体包体积 | 安装包变大 | 只打包 GB2312 子集（3–5 MB） |
| **磁盘增长快** | **实测约 18.7 GB/年**（单期 62.7 MB），远超早期 6.5 GB 的估算 | 存储管理页可清理；可选「跳过广告版」可省约 51%/期 |
| **广告版体积畸大** | 单期 51% 存储被 3 个广告版占掉（14.13 / 12.38 / 5.60 MB） | **已决策：完整存档，不做跳过**（2026-10-29）。理由：存档价值在于与当日报纸一致；18.7 GB/年可接受 |
| macOS 未签名 | 无法分发 | M4 再处理；当前保证源码可跑 |
| 版权 | 法律风险 | 纯个人本地；无分享功能；README 声明 |
