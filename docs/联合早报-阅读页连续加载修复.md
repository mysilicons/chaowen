# 联合早报阅读页连续加载修复

日期：2026-10-30。

## 问题与原因

- 首页触底监听只连接首页的滚动控制器，阅读页左侧文章目录没有连接分页监听，也没有分页状态或重试入口。
- 「下一篇」仅判断当前文章是否为已加载列表的末篇，没有考虑服务端仍有下一页，因此提前禁用。
- 分页请求使用文章选择代次判定响应是否有效，阅读中切换文章或返回目录时可能丢弃本会话的分页响应，并让加载状态无法复位。

## 修复行为

- 阅读页目录接近底部时调用与首页相同的分页操作，追加更早的文章，当前正文不受影响。
- 目录底部复用加载中、加载更早文章、失败重试和已到末尾的状态。
- 当前文章位于已加载末尾但仍有后续页时，「下一篇」保持可用；点击后获取下一页并打开新增的下一篇，等待期间防止重复点击。确认没有更多数据后才禁用。
- 分页结果按来源会话代次校验，翻篇不取消分页；离开来源、重新进入或手动刷新仍会使旧会话结果失效。
- 同一会话共享正在执行的分页 Future，避免目录触底与下一篇同时触发重复请求。用户等待期间主动切换文章时，不再自动跳回旧目标。
- 分页失败保留当前正文，在阅读页显示错误，可再次点击下一篇或目录中的重试按钮；窄窗口同样能看到错误。
- 延续早报不持久化和不显示摘要的要求。

## 实施记录

1. 阅读当前阅读视图、分页客户端和界面测试，确认后端分页已经可用，本次修改前端行为即可。
2. 先增加目录触底与末篇下一篇测试，分别观察到分页请求次数实际为 0、预期为 1 的失败。
3. 增加阅读目录控制器和公共触底判断，复用分页页脚；将会话代次与文章选择代次分开，合并同会话的在途分页请求。
4. 增加末篇下一篇等待加载与跳转逻辑，覆盖加载期间主动切换文章的情形。
5. 将错误重试用例切换到窄窗口，观察错误提示不可见的失败，再补上阅读页公共错误提示。
6. 新增四项回归：阅读目录触底、末篇加载并跳转、窄窗口分页失败重试、分页期间切换文章。
